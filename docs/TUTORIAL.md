# 画像制作を一周する

## 1. 作業場所を決める

ソースコードの場所と、画像データの場所を区別する。ランチャーの既定はキット内の `workspace/`。別の場所を使う場合は `python -m stylekit --workspace <path> init` を実行し、以降も同じ `--workspace` を指定する。CLIはキットのフォルダで実行する。

エージェントには `AGENTS.md` と image-workflow スキルを読んでもらう。`doctor` で設定とComfyUI接続を確認できる。

## 2. 最初の絵柄を登録する

画面右上の「絵柄を登録」から、名前・自分のComfyUI内のチェックポイント名・線や塗りの表現を入力する。モデルファイルはキットへアップロードされない。

詳細なモデル・LoRA・サンプラー・Detailer設定はエージェントがレシピJSONを作り、`style create --id <id> --name <name> --recipe <file>` で登録できる。`style show --id <id>` で内容とハッシュを確認できる。

登録済みIDを上書きすることはできない。最初の絵柄を調整して残す場合も、派生として保存する。

## 3. セッションを始める

左の絵柄から「この絵柄で新しく始める」を選ぶ。別セッションは毎回、その保存済み設定から始まる。ほかのチャットの最近の調整を取り込まない。

「今回描きたいもの・要件」と「今回だけ除外したいもの」を入力する。例えば公園、飲料を持たない、今回だけ表情を変える、といった指定はここに置く。線・塗り・雰囲気を持続的に変えて試す場合はエージェントがセッションの `adjustments` を使う。これも保存済み絵柄を変更しない。

## 4. エージェントに生成を頼む

「エージェントへの依頼文をコピー」をチャットへ貼る。依頼文にはセッションIDと新しいターンIDが入る。エージェントは自然言語の要件をモデルに合うプロンプトに整理し、そのセッションで試す。

```sh
python -m stylekit --workspace <path> session show --id <session_id>
python -m stylekit --workspace <path> session update --id <session_id> --patch <patch.json>
python -m stylekit --workspace <path> generate --session <session_id> --turn <turn_id> --seed 123456
```

パッチには現在の `revision` が必要。ほかの画面の更新を古い内容で上書きすることを防ぐ。
ComfyUIは既定で `http://127.0.0.1:8188`。変更は `init --comfy-url <url>`。この操作だけでは生成しない。

## 5. 番号付きレビューで評価する

生成結果をまとめる：

```sh
python -m stylekit --workspace <path> review create --turn <turn_id> --reference <past_run_or_experiment_ids...> --title "今回の画像"
```

各バッチの画像を一つずつ選び直さなくても、同じターンの候補をまとめられる。過去の比較対象も同じ番号付きセットに入る。短い表示名は `--labels <JSON file>` で指定できる。

- 左のサムネイルか ← → キーで切替。
- 原寸／＋で拡大、ドラッグで移動。
- 「横に比較」で過去画像と見比べる。
- Fキーで全画面。左下のサムネイルと操作ボタンは2.4秒無操作で消える。
- 評価は4択、メモだけでもよい。下書きは自動保存。
- 「評価を確定」を押し、依頼文をチャットへ貼る。

エージェントは `review show --id <id> --feedback` で確定内容を読む。nullなら未確定。評価を付けただけで絵柄は保存・変更されない。

## 6. 気に入った雰囲気を保存する

セッション画面で名前を付け、「新しい絵柄として保存」を選ぶ。元の絵柄、ほかのセッションの選択、今回だけの要件はそのまま。

特定の画像の雰囲気を残す場合はエージェントに画像番号を伝える。エージェントはその番号のrun IDを使う：

StyleForkで生成・登録した画像には、レビュー画面の「この画像の絵柄を保存」ボタンも表示される。名前を入力して保存すれば、その画像のrunに対応するレシピから派生を作れる。古い研究画像などrun情報がない画像は、エージェントに生成条件を確認してもらう。

```sh
python -m stylekit --workspace <path> session fork --id <session_id> --style-id <new_id> --name "新しい絵柄" --run <run_id> --save-intent "ユーザーの保存指示"
```

生成後に別の調整をしていても、この方法なら指定画像のレシピを参照できる。被写体や今回だけの除外条件は含めない。保存した絵柄を次に使う場合は、その絵柄から新しいセッションを始める。

## 7. Driveで見る場合

`drive-plan --turn <turn_id>` は、画像だけの同期計画を出す。Drive連携のあるエージェントが、自分のアカウントで同じ相対フォルダ構成を用意して同期する。既定ではDriveを使わない。

既存ファイルはIDを保って更新し、移動前には現在の親フォルダを確認する。認証情報はコードやJSONの生成条件に保存しない。
